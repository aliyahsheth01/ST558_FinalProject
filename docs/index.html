Predictive Modeling of Tablet Manufacturing Data

Author

Aliyah Sheth

Introduction

This project uses the tablet manufacturing dataset introduced in ST 558 Project 2. The data contain 4,850 tablet records from 52 compression lots across three strengths: Low, Mid, and High. Records come from two engineering studies and one registration campaign.

Available measurements include tablet weight, thickness, and hardness (tablet breaking force). Measurement availability varies across records, so missing values will be reviewed before selecting the modeling data.

This analysis will compare a tree model and a random forest for a selected prediction task. The selected model will then be made available through an API running in a Docker container.

Preparing the modeling dataset

I restore missing Registration target hardness values using the predefined settings documented in Project 2: 4 kp for Low strength and 7 kp for Mid and High strengths. Existing targets are retained. These values come from documented manufacturing settings rather than estimates calculated from measured hardness.

I store the prepared records separately from the original imported data. Strength, sampling point, and speed setting are represented as categorical variables using factors.

# I create a prepared copy of the imported data.
prepared_data <- tablet_data |>
  mutate(

    # I restore missing Registration targets using the
    # predefined values and retain existing targets.
    target_hardness_kp = ifelse(
      study == "Registration" & is.na(target_hardness_kp),
      ifelse(strength == "Low", 4, 7),
      target_hardness_kp
    ),

    # I represent the three strengths as categories.
    strength = factor(
      strength,
      levels = c("Low", "Mid", "High")
    ),

    # I specify the sampling categories in process order.
    sampling_point = factor(
      sampling_point,
      levels = c("Pre-Start", "Beginning", "Middle", "End")
    ),

    # I represent each speed configuration as a category.
    speed_setting = factor(speed_setting)
  )

# I retain records with an observed hardness response.
# I keep the response, four predictors, and tracking columns.
model_data <- prepared_data |>
  filter(!is.na(hardness_kp)) |>
  select(
    tablet_id,
    study,
    blend,
    lot,
    sample_id,
    hardness_kp,
    strength,
    target_hardness_kp,
    sampling_point,
    speed_setting
  )

Records without measured hardness are excluded because an observed response is needed for model fitting and evaluation. Prediction Goal and Predictors

I will compare a regression tree and a random forest for predicting measured hardness for an individual tablet. The response variable is hardness_kp, which records tablet breaking force in kiloponds (kp).

The initial prediction question is: How accurately can tablet hardness be predicted using tablet strength, target hardness, sampling point, and speed setting?

The following four variables will be considered as predictors:

Predictor Meaning Reason for inclusion
strength Low, Mid, or High tablet strength The strengths have different tablet characteristics and intended hardness levels.
target_hardness_kp Intended hardness setpoint The intended hardness may help explain the measured breaking force.
sampling_point Pre-Start, Beginning, Middle, or End Hardness may vary across the compression run.
speed_setting Nominal setting or turret/feeder speed combination Operating speed may be associated with differences in measured hardness.

Target hardness is the intended setpoint, distinct from the measured hardness response. Missing Registration targets are restored using the documented presets described in the data preparation section.

Evaluation Metric

I will use root mean squared error (RMSE) as the primary metric for tuning and comparing the models. RMSE measures prediction error in the same units as the response, so the results can be interpreted in kiloponds.

RMSE gives greater weight to larger prediction errors. I chose this metric because substantial errors in predicted tablet hardness are particularly undesirable for this prediction task. Lower RMSE indicates better predictive performance.

Training/Test Split and Cross-Validation

Training/test split

I randomly split the modeling records into approximately 70% training data and 30% test data. I set a seed for reproducibility and stratify by strength to preserve the representation of Low, Mid, and High tablets in both sets.

The training data will be used for model fitting and cross-validation. The test data will be reserved for comparing the selected tree and random forest after tuning.

This split assigns individual tablet records. Records from the same lot or sample may therefore occur in both sets. Performance estimates will describe held-out tablet records within the manufacturing groups represented in this dataset. Evaluation of entirely new lots or blends would require separate grouped validation.

Five-fold cross-validation

I create five cross-validation folds using only the training data. I stratify by strength to maintain similar proportions of Low, Mid, and High tablets across the folds.

For each tuning configuration, the model will be fitted using four folds (the analysis set) and evaluated using the remaining fold (the assessment set). Each training record serves in an assessment set once. The average assessment RMSE across the five folds will guide tuning within each model family.

Both the regression tree and random forest will use these same folds. The record-level grouping limitation described above also applies to cross-validation.

Modeling recipe

I define a common recipe for both model families using the training data. Measured hardness is the response, and the four predictors are strength, target hardness, sampling point, and speed setting.

Listing the predictors explicitly excludes the record, study, blend, lot, and sample identifiers from the model inputs.

The selected variables are complete after data preparation. I retain categorical predictors as factors and target hardness in its original units. The planned tree engines can use these variable types directly, so this recipe requires no additional transformation steps.

# I specify the response and the four intended predictors.
tablet_rec <- recipe(
  hardness_kp ~ strength + target_hardness_kp +
    sampling_point + speed_setting,
  data = tablet_train

Tree Model

How a regression tree works

A regression tree predicts a numeric outcome by repeatedly dividing records into two groups according to predictor values. Numeric predictors can be split at a threshold; categorical predictors can be split into groups of levels.

At each node, the algorithm chooses the available split that most reduces the sum of squared deviations from the means of the resulting groups. This process repeats within the groups. It is a greedy procedure: it selects the best immediate split without searching every possible complete tree.

A new tablet follows these rules to a terminal node, or leaf. Its prediction is the mean hardness of the training records in that leaf. Trees can capture nonlinear patterns and interactions, but deep trees may overfit and can change substantially when the training data change. I will use cross-validation to select tree complexity.

Model specification and tuning grid

I use the rpart engine in regression mode because measured hardness is numeric. I tune tree depth and cost complexity while holding the minimum node size parameter at 20.

Parameter Values considered Meaning
tree_depth 1, 3, 5, 7, 9 Maximum number of splits along a root-to-leaf path
cost_complexity 0.0001, 0.001, 0.01, 0.1 Complexity penalty; larger values favor smaller trees
min_n 20, fixed Minimum number of records required for a node to be considered for further splitting

The depth values cover shallow through more flexible trees. The complexity penalties span several orders of magnitude to compare weaker and stronger restrictions on tree size.

This grid contains 20 parameter combinations. I will compare them using the existing five cross-validation folds and select the combination with the lowest mean assessment RMSE.

# I define the tree model and identify the parameters to tune.
tree_spec <- decision_tree(
  tree_depth = tune(),
  cost_complexity = tune(),
  min_n = 20
) |>
  set_engine("rpart") |>
  set_mode("regression")

# I combine the shared recipe and tree specification.
tree_wf <- workflow() |>
  add_recipe(tablet_rec) |>
  add_model(tree_spec)

# I create four complexity values and five depth values.
# Cost-complexity ranges use the log10 scale.
tree_grid <- grid_regular(
  cost_complexity(range = c(-4, -1)),
  tree_depth(range = c(1L, 9L)),
  levels = c(4, 5)
)
